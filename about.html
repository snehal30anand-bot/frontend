About Satellite.IO

Empowering environmental analysts and researchers with accessible, high-performance satellite image processing directly in the browser.

Our project addresses the challenge of handling massive, multi-band satellite imagery by providing a streamlined platform for automated analysis, linking directly to your presentation's **Problem Statement** and **Proposed Solution**. We enable rapid calculation of essential indices like NDVI, advanced classification, and cloud removal.

How It Works: Technology and Methodology

Technology Stack (The Engine)

We utilize a robust full-stack architecture. The **Front-end** (HTML/JS) provides the user interface for upload and visualization. The **Back-end (Node.js/Express)** handles secure user authentication and job queuing.

The core processing (**Phase-1 Implementation**) leverages optimized libraries (e.g., Python's GDAL or Rasterio, accessible via a server-side API) to perform complex geospatial calculations efficiently, ensuring fast turnaround times for large datasets.

Processing Methodology (The Brain)

  • **Data Validation:** Images are immediately checked for correct band structure and georeferencing upon upload.
  • **Job Queuing:** Processing requests (like calculating NDVI) are added to a queue to manage server load and resource allocation.
  • **Parallel Processing:** The system breaks down large images into smaller tiles, processing them concurrently to reduce overall computation time.
  • **Result Storage:** Processed outputs (like derived raster images) are stored in secure locations, with metadata tracked in the **Database** for easy retrieval.

User Workflow: The Project Flow

1

Authentication & Access

User **Registers** or **Logs In** securely. This creates a session token, granting access to their private dashboard and ensuring data separation (linked to the `users` table).

2

Image Upload & Metadata Storage

The user uploads a satellite image (the **Browse Photos** step). The image file is saved to storage, and metadata (path, filename) is recorded in the **`images`** table.

3

Job Creation & Execution

The user selects a **Processing Type** (e.g., NDVI) and clicks "Process." A new record is created in the **`processing_jobs`** table, marking the job as **'RUNNING'**.

4

Result Retrieval & Visualization

Once the job is **'COMPLETE'**, the user is notified. They can then retrieve the processed image (via the `result_path`) and view the analysis directly in the application.
